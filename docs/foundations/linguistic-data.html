Turning linguistic records into data

Suppose we have made a recording of a speaker producing the word heed. What is the observation in this recording?

There is no single answer. We might represent the recording as one waveform, as one word token, as one vowel token, or as a sequence of acoustic measurements taken through the vowel. The recording contains information that supports each representation. It does not choose among them.

This is the first decision in a statistical analysis: what does one observation represent? The entity represented by one observation is the unit of analysis.

NoteReading: White et al. (2020), Section 2

White et al., The Universal Decompositional Semantics Dataset and Decomp Toolkit.

Read Section 2, Data.

Why this reading? The section begins with English Web Treebank sentences and derives several distinct objects from them: syntactic graphs, semantic graphs, and semantic attributes. It shows concretely why a stored source and an observation used in an analysis are not the same thing.

Begin with the stored record

A record is a stored artifact. Recordings, corpus documents, response logs, and annotation files are all records.

One record may contain many possible observations. A ten-minute interview is one audio file, but it may contain hundreds of word tokens and dozens of vowel tokens. Conversely, several records may contribute information about one observation. If we summarize a speaker across three recording sessions, the speaker-level observation draws on three files.

File count thus tells us how the material is stored. It does not tell us how many observations the analysis contains.

Decide what one row means

Consider a reading-time experiment. Each participant reads several sentences, and each sentence contains several regions. The response log might look like this:

participant sentence region reading time
p01 s17 1 318
p01 s17 2 441
p01 s18 1 287

If one observation is one participant’s reading of one region in one sentence, then a row is identified by three pieces of information:

\langle\text{participant},\text{sentence},\text{region}\rangle.

We can check this claim directly. p01 does not identify a row because that participant appears repeatedly. (p01, s17) still does not identify a row because the sentence has several regions. Adding the region makes the identifier unique in this design.

The smallest collection of columns that uniquely identifies an observation is its observation key.

NoteA quick key check

If two rows share the proposed observation key, either the key is incomplete or the proposed unit was measured repeatedly. We need to know which before fitting a model.

Watch what aggregation changes

Suppose we sum the regional reading times within each participant and sentence. The new table has one row per participant and sentence, so the region column is no longer part of the key.

Suppose we then average across participants. The new table has one row per sentence. The participant column is no longer part of the key either.

Each step changes the question the table can answer:

one row represents variation still visible
participant, sentence, and region participants, sentences, and regions
participant and sentence participants and sentences
sentence mean sentences

Once we replace 100 participant responses with one sentence mean, the resulting table cannot show how participants differ on that sentence. That information was removed before the statistical model saw the data.

Aggregation is not always wrong. It is a transformation with consequences. We need to determine what information the transformation discards.

Tokens and types

Linguists often switch between tokens and types. A token is an occurrence in a particular context. A type groups occurrences that the analysis treats as equivalent.

Consider ten occurrences of runs. They are ten orthographic word tokens. They belong to one word-form type, runs. A lemmatized analysis may group them with occurrences of run, ran, and running under the lemma run.

There is nothing automatic about the grouping. A study of inflection must distinguish run from runs. A study of lemma frequency may deliberately collapse them.

The choice changes the unit:

question useful unit
Does discourse context affect the choice of a dative construction? one construction token
Do verbs differ in their preference for the dative construction? one verb type, perhaps summarized across tokens
Does one speaker change construction use over an interview? one speaker by time segment observation

The first analysis preserves contextual variation among tokens. The second emphasizes lexical variation among types. Neither representation is generally better. They support different comparisons.

Repetition remains repetition

A rectangular table does not claim that its rows are independent. In the reading-time table, participant p01 occurs in several rows and sentence s17 occurs in several rows. Those repetitions remain present even if every row has a unique observation key.

This distinction is easy to miss:

  1. a unique key tells us that two rows are not the same observation;
  2. repeated identifiers tell us that two observations share a participant, item, speaker, word, language, or another source of variation.

Later models can represent these shared sources. At this stage, the important step is to retain the identifiers in the table.

Keep three levels separate

Three questions help diagnose a proposed dataset.

First, where was the response measured? A judgment might be recorded on every participant and sentence trial.

Second, what does one response in the analysis represent? We might retain each trial or average the judgments by sentence.

Third, what should the claim generalize to? We might want a statement about the tested sentences, new sentences of the same constructions, the tested participants, or a broader population of speakers.

These answers need not be identical. A trial-level analysis may support generalization to new participants and new items when the design contains replication across both. But many tokens from one speaker do not supply replication across speakers. More rows at one level do not create information at another level.

Write the unit before analyzing the response

Before plotting or modeling, complete this sentence:

One observation represents ______.

Then ask:

  1. Which columns uniquely identify that observation?
  2. Which speakers, items, words, languages, documents, or sites repeat?
  3. Which variation has already been removed by preprocessing or averaging?
  4. Does the dataset contain replication at the level of the intended claim?

For a corpus of dative tokens, a useful answer might be:

One observation represents one attested dative construction token. The observation key combines the document and token position. Speakers, verbs, and documents repeat across observations. The analysis retains both lexical and discourse-context variation.

This statement does not yet choose a probability distribution or regression model. It tells us what those later models must represent.

Test the distinction

  1. A corpus contains 50,000 word tokens from 20 interviews with five speakers. Give an observation key for a token analysis. Then describe a speaker-level table and state which variation the aggregation removes.
  2. An acceptability experiment presents 40 sentences to each of 100 participants. What does one row represent if the table contains one judgment per row? Which identifiers must be retained?
  3. A typological database contains two inventories for the same language from different sources. Is language a sufficient observation key? What additional identifier is needed?
